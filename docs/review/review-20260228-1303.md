# Review Report

## 1) 摘要
本次提交（`e621142`）修复了上轮指出的两个方向性问题：`count_tokens` 口径对齐与 compaction 摘要基于裁剪后消息。  
但引入了一个高严重度回归：内部字段 `_pruned_messages` 被保留在上游请求体中，导致请求可能在客户端参数绑定阶段直接失败，或在调试日志序列化时失败。

## 2) 问题清单

### 高

- `_pruned_messages` 泄漏到上游请求参数，可能导致所有主链路请求失败  
  - 证据：
    - 新增内部字段写入请求：`src/conversion/request_converter.py:293`
    - 主路径仅清理 `_input_tokens`，未清理 `_pruned_messages`：`src/api/endpoints.py:124`, `src/api/endpoints.py:162`
    - 上游调用使用 `self.client.chat.completions.create(**request)`，严格关键字参数，不接受 `_pruned_messages`：`src/core/client.py:71`, `src/core/client.py:151`
  - 影响：
    - 触发 `TypeError: got an unexpected keyword argument '_pruned_messages'` 或等价异常；即使未触发，也会把内部字段错误传给上游。

- 调试日志会对含 `_pruned_messages` 的请求执行 `json.dumps`，对象不可序列化可直接抛错  
  - 证据：
    - `openai_request["_pruned_messages"]` 保存的是 `ClaudeMessage` 对象列表：`src/conversion/request_converter.py:293`
    - 非流式分支日志：`json.dumps(openai_request)`：`src/api/endpoints.py:225`
    - 客户端日志：`json.dumps(request)`：`src/core/client.py:66`
  - 影响：
    - 即使日志级别不是 DEBUG，f-string 仍先求值，可能在日志调用前抛 `TypeError: Object of type ClaudeMessage is not JSON serializable`。

### 低

- 当前测试仍未覆盖关键异步路径（本地 `pytest -q` 为 skipped），对该类回归缺乏自动保护。

## 3) 修改建议

- 在任何上游调用前统一剥离内部字段（至少 `_input_tokens`, `_pruned_messages`）。  
- 对调试日志改为惰性序列化或使用可序列化副本，避免直接 `json.dumps` 含 Pydantic 对象的结构。  
- 增加回归用例：验证请求体不会包含内部字段、日志路径不会触发序列化异常。

## 4) 一致性校验（仅本次提交范围）

  - `/v1/messages/count_tokens` 返回 effective 口径：`src/api/endpoints.py:455-457`
